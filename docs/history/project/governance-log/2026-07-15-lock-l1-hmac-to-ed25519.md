# 治理记录:ARCHITECTURE-LOCK 不变量 L1 — HMAC 纠正为 Ed25519

**日期**:2026-07-15(b 会话)
**改了什么**:`docs/architecture/ARCHITECTURE-LOCK.md:78` 不变量 L1,单点纠错:
`靠 HMAC 验签而非 ring 门控` → `靠 Ed25519 签名验签而非 ring 门控`。**只换算法名,句子其余一字未动。**

## dwgx 为什么授权(3 次确认)

`ARCHITECTURE-LOCK.md` 是 `status: locked` 冻结文档,改需 ADR + owner 明确确认。
dwgx 原话:**"'HMAC'改成'Ed25519 我确认三次"** —— 明确给出 3 次确认授权,针对性地只批这一处算法名纠错。

## 为什么这是"纠错"而非"改架构"(所以不需要走完整 ADR)

L1 不变量的**架构决定**是:"compat 补丁的应用靠**签名验签**、而非 ring 门控;验签失败即拒。"
这个决定**没有变,一个字没动**。变的只是**算法名**——L1 写的"HMAC"是 2026-07-12 的旧稿,而 2026-07-13 加密线落地时
实际实现的是 **Ed25519**(`Ed25519PatchSigner` + TUF L0-L3,提交 `d77f832`…`34d211c`)。
即:**冻结的应是架构决定(靠签名),不是当时随手写下的、后来被真实现取代的算法名。**
locked 文档冻结一个**假的实现细节**,比不冻更危险——本次文档矛盾审计(Opus 4.8)的最严重发现就是:
一个 AI 读到 L1 的"HMAC"会去"实现 HMAC 签名器"或改掉真正的 Ed25519 签名输入 = **破坏已落地的安全脊柱**。
