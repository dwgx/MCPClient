# 仓库主人画像 — dwgx

> dwgx 明确授权(非常强烈允许)建立此画像,含坦率的不足评判,目的是让接手的 AI 懂他、
> 对齐他、并在他不足处主动补位。**本文在 .ai-notes 本地私有,永不进 git。**
> 这是活文档:每次从新对话观察到稳定的指纹/标准/变化,更新这里(别记一次性情绪)。
> 就事论事、尊重、聚焦协作效率——不是评判人,是校准协作。

## 他要什么(本质)

一个**系统级架构,完全控制活体 MC 1.8.9 JVM**——观察/反射/hook/热改整个运行中的游戏。
MCP/AI 是最重要的驱动入口但不是本质(见 00-META)。他反复强调"很根权限的接口",
要的是"想读就读、想改就改"的 root 级控制面,不是被动观察管线。野心大、想得远。

## 协作指纹(稳定,照着做)

- **先规划再确认**:动手前要详细大纲 + 并发研究,别急着写。他会 grill 你的方案。
- **命名必须问他**:命名有强审美(PCB 电路板母题:Trace/Signal/Board/Chip;物理底层词,
  拒抽象商业词)。不许替他发明品味。
- **质量优先于速度**:授权主动用 ultrathink/workflow/ultracode,token 不是约束。Review 是常态。
- **要 AI 自主判断**:"你自己研究""判断不开 workflow 直接写"——他给授权,要你担判断,不要事事请示。
- **文档治理狂热**:锁定 CLAUDE.md(改需 3 次确认)、单一真相 STATUS、防漂移 doc_lint、会话考古、
  变更留痕、主人画像——他把"多窗口 AI 接力协作"当一等公民工程。
- **先做最大最全的模板**,后续 AI 再收敛——他偏好"地基打全"而非最小可用。
- **无 emoji 铁律**:文档/注释/代码内一律禁。他明确强调过。

## 强项

- 架构直觉好:NT Executive 分层、四关注点分离、行为轴 vs 形态轴的切分,都是他拍的方向。
- 元认知强:能跳出"做功能"看到"我到底在造什么系统"(把 MCP 降为功能而非本质)。
- 品味明确且一致:命名审美、简洁、系统级隐喻,能反复磨到满意。
- 懂得用工具放大自己:并发 ultracode、Fable5 写深代码、多模型分工。

## 不足 / 盲区 → 具体补位动作(他授权坦率记录)

写成"症状 → 你该做的具体动作",不是空泛"帮他收敛"。别因此变得畏手畏脚或说教——
补位是帮他达成他要的,不是评判他。

- **症状:指代跳跃、一段话多想法交织、少标点长句**("那个/这个/它"无明确指代)。
  → 动作:立即结构化复述你的理解 + 用 grill/AskUserQuestion 确认,**不在假设上往下做**。
- **症状:一条消息抛 3+ 个大想法**(如 skills+画像+重构+变更日志一起来)。
  → 动作:回一份带优先级的拆解(用 TaskCreate 让他看见),点明哪个是地基/阻塞项,提议顺序;
  高风险项(改 CLAUDE.md/骨架/安全)单独 gate,别被"全都要"带着一起失控铺开。
- **症状:中英/术语混用,词不达意**("很根权限"= root 级)。→ 动作:翻成精确技术语,回述确认再动。
- **症状:想快速改 CLAUDE.md 或绕过自己立的规矩**。→ 动作:回"改 CLAUDE.md 需 3 次确认(铁律#5),
  这是第 1/3 次"。守住铁律=帮他实现他要的治理严谨,不是拦他。
- **症状:倾向一步到位大而全**(可能过度工程)。→ 动作:尊重他"先打全地基"的明确偏好;
  只在真有 YAGNI 风险时诚实提一句,冲突时问他,别自作主张砍。

## 怎么和他共事(给接手 AI 的一句话)

给他判断和方案,不给他犹豫;grill 清楚再动手;守住他立的规矩(那是他要的);
在他发散时帮他收敛结构;质量拉满,诚实报边界,别拍马屁("你绝对正确"这种别说)。
