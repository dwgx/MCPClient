## 7. 第一次真跑之后：北极星的硬约束（2026-09-30 晚）

### 7.1 我跑的第一局，以及它教会我的事

`first_night.py` 第一次执行了北极星。结果不是"失败"，是**它准确定位了失败**：

| 现象 | 真相 |
|---|---|
| 挖掘 6 步全部 `refused` | **我的 harness 传错了参数名**（`mode` 而非 `status`）。harness 如实记录了六次拒绝，没有假装造出庇护所 |
| 22 分钟里 `time` 始终 = 9 | **游戏被暂停**（ESC 菜单开着 + 失焦暂停）。集成服务器不 tick，世界时钟不走，**夜永远不会来** |
| 看起来"悬浮在虚空" | 暂停在半空时的渲染；`onGround` 其实是 true |

**第二个才是真问题，而且它一直藏在那里**：一个等天亮的 harness，如果分不清
"夜还没到"和"这里根本没有夜"，那它不是在测量，是在等一个自己从未检查过的条件。
现在 `ensure_running()` 是一道硬闸：取消暂停、关掉任何屏幕、然后**在 2.5 秒内验证时钟真的在走**；
`wait` 循环另有 30 秒冻结熔断。修复后实测 `time = 118 → 159 → 200`。

### 7.2 CrazyBadger 分解出的硬约束：2x2 合成栏不可达

十阶段分解里，**三阶段用现有工具做不到**，且卡点是同一个：

> **没有任何工具能按下原版背包键 'E'。**
> `gui_press_key` 只驱动 `GuiScreen.keyTyped`，而 'E' 是 `Minecraft.runTick` 里读的
> `KeyBinding`，不是 GuiScreen 的字符事件。`do_click_slot` 在 windowId 0 上又需要背包界面已打开。

于是整条链断在第一环：

```
log --(合成)--> planks --(合成)--> sticks --(合成)--> crafting table
     --(合成)--> torch --(合成)--> wooden pickaxe --> bed
```

而 `log -> planks` 是 1x1 配方，**合法地放进得下 2x2 栏**——所以失去 2x2 栏就失去上面全部。

**没有 2x2 栏，唯一活路是徒手**：挖泥土/沙子/砂砾/树叶，垒一个带顶的 2 格高盒子，
撑过约 8 分 20 秒，饿了吃生猪（猪可以徒手打死）。睡觉在普通开局做不到——床只在世界里
已存在（村庄）且夜里 8x5x8 内没有敌对生物时才生效。

`seam_glfw_key_hook` 是**观察器**（GLFW → EventBus），不是注入器，所以这条路确实没通。

### 7.3 由此得出的 build-next（只有一条）

**一个能注入原始按键的工具**——即调用 vanilla 的 `KeyBinding.onKey(keyCode, scancode, action, mods)`，
那正是 LWJGL 回调喂给 `KeyBinding` 的入口。这不是"绕过 UI 直改状态"：它走的**就是**真人按键走的
那条路径，`Minecraft.runTick` 随后会像对待真人按键一样调用 `KeyBinding.onTick`。

这条解锁 planks / sticks / 工作台 / 火把 / 镐 / 床，也解锁"用火把把光照提到 7 以上"
这条真正的反刷怪手段。

ARCHITECTURE-LOCK §5 明确：**新工具（登记 ring）属于加法式扩展，不需要 ADR**。
所以这是允许的改动；它要登记 ring，但不触碰 L4 的按名侧表语义。
