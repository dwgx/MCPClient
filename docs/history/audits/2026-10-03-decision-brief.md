## 1. 决策一：模型接缝该走生产还是留 test 树

### 事实（主 agent 亲验）

`ModelRound` 的 6 个文件（实测 108 KB）**全在 test 树**，
且模型的动作走 `ModelPolicy` → `ActToolsHeadless` → `InteractApplier`，
**绕过了 `IoManager.java:135-136` 的七层门与 L7 schema 校验。**

而 **Owner 的 R1 是**：「操控的话 MCP 绝对是最完美的」，
解码成「每项游戏内能力必须有且只有一个 MCP 工具出口」。
**一条绕过 `IoManager` 的路径恰好是那条约束的反面。**

### 三个选项

| 选项 | 内容 | 代价 |
|---|---|---|
| **A** | 接缝进生产树且必须过门 | **最大架构动作**：需要 main 树的世界抽象 + main 树的 harness |
| **B** | 留 test 树，把「这是替身工具面」写进每份产物 | **结论不可迁移到活客户端**，而北极星是活客户端那一侧 |
| **C** | 先 B 拿到一个诚实标注的判决，再决定要不要 A | 推迟那个决定 |

### 我的判断：**C**

**理由**：它会先告诉我们「模型会不会自己发现 `act_set kind='craft'`」——
**而那个答案决定 A 值不值得做。** 在那个答案出来之前做 A，
是在不知道收益的情况下付最大成本。

**但有一个前提条件**：C 只在「那一局能跑完」时成立。
**而 2026-10-03 的两局都没跑完**（一局测了工具面，一局 14/14 超时），
第三局正在跑。

### 我的判断：**高优先级，且与决策一同做**

**理由**：如果只做决策一而不做这一件，会出现一个荒谬状态——
**模型接缝搬进生产树，而它要满足的两个判据仍然只在夹具里成立。**

**而 `DistanceColumn` 那一列给出的量化更刺眼**：
