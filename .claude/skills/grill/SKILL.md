# Grill — 逼问到决策树见底

灵感来自 mattpocock/skills 的 grilling。本项目采纳它,因为它正中 dwgx 的协作指纹:
先规划再确认、命名必须问我、不许自作主张。见 `.ai-notes/docs/project/owner-profile.md`。

## 什么时候用

- 需求含糊,或你脑子里冒出"我猜他是想……"——那就别猜,grill。
- 一个任务有多条合理路径(架构、命名、取舍),动手前先把岔路问清。
- 涉及安全内核 / 冻结骨架 / CLAUDE.md 等不可轻改的东西。
- 用户明确说"先规划再确认""你问我方向"。

## 怎么做

1. **摊开假设**:把你对需求的理解逐条列出,每条标"确定 / 猜的"。
2. **画决策树**:找出所有分岔点(方案 A/B、命名母题、边界画在哪、做/不做)。
3. **逐个分支逼问**:一次问一组相关的岔路,给选项 + 你的推荐(第一项标"推荐")+ 推荐理由。
   优先用 AskUserQuestion(给单选/多选 UI)。**已知 bug:本环境偶报 array 格式错,但答案仍会传回——
   报错也去读用户回答**;反复失败就改用消息里文字编号选项问,别让工具错误卡住收集决定。
4. **循环到见底**:每个分支都定死了才停。没定死的分支不许进实现。
5. **回述锁定**:把用户所有决定汇成一句话清单,让他确认"就这样"。

## 铁规矩

- **别用一个问题换用户一次点头就当全批了。** 分支各自都要定。
- 命名、架构取舍、动骨架——这些必须问,不许替 dwgx 发明品味。
- 问题要给推荐(第一项 + 标"推荐"),但推荐不是替他决定。
- Grill 完才允许调用实现类工具。研究/只读探查不需要先 grill。
