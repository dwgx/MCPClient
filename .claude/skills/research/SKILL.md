# Research — 一手来源优先的调研

灵感来自 mattpocock/skills 的 research + ECC 的 research-first。本项目抗-LLM 混淆 Wave1/2 就是这么做的。

## 什么时候用

- 探索性问题(不是"改这行代码",而是"这条路可不可行/怎么设计最好")。
- 选型、对比、需要广度覆盖多个独立方向。
- 抗逆向 / 安全研究这类必须拿真实证据说话的。

## 怎么做

1. **拆方向**:把问题切成独立子方向(能并行的),别一个 agent 串行扛。
2. **派 subagent 并行**:每个 subagent 一个方向,给 schema 让它返回结构化结论,不是散文。
   - 控 token:探索性研究用轻模型(sonnet)+ 低工具轮次 + 高并行度(上个交接的教训:workflow 别太慢)。
3. **一手优先**:源码 > 官方文档/规范 > 高质量博客 > 二手转述。标明每条结论的来源。
4. **综合与判断留给主 agent**:subagent 出素材,"我的意见/取舍"由主 agent 做,别外包判断。
5. **诚实边界**:研究结论必须写清"什么没验证/什么是假设/墙有多硬"。别把减速带当城墙。

## 铁规矩

- 只读调研不改代码,不需要先 grill;但要**落地**研究结论(建文档/改架构)前,先规划再确认(dwgx 铁规矩)。
- 永久有用的非显然事实 → 固化进对应文档或 ~/.claude 持久记忆,别让下一个 AI 再查一遍。
- 旧窗口"当时为什么这么做"用 session-search.py 考古,别当现状——现状以 STATUS + 代码为准。
